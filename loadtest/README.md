# WeDo Load Testing

Нагрузочное тестирование выполняется через Locust against локальный Docker-стенд.

## Подготовка

1. Установить зависимости:

```bash
pip install -r requirements.txt
```

2. Запустить backend и PostgreSQL через Docker:

```bash
docker compose up --build
```

3. Проверить доступность API:

```bash
curl http://127.0.0.1:8000/api/openapi.json
```

## Основной прогон

Профиль нагрузки для дипломного замера:

- 50 виртуальных пользователей
- разгон 5 пользователей в секунду
- длительность 5 минут
- HTML-отчет `loadtest/report.html`

Команда:

```bash
locust -f loadtest/locustfile.py --host http://127.0.0.1:8000 --users 50 --spawn-rate 5 --run-time 5m --html loadtest/report.html --headless
```

Для интерактивного режима можно запустить без `--headless`, открыть `http://localhost:8089` и указать те же параметры в интерфейсе Locust.

## Сценарии

Сценарий имитирует работу пользователя:

- регистрация основного пользователя и пользователя-организатора;
- получение JWT-токенов;
- выбор существующей активности из списка;
- просмотр списка и карточки активностей;
- сохранение активности;
- вступление в активность;
- просмотр участников;
- просмотр уведомлений;
- генерация QR-токена;
- попытка поставить рейтинг.

Создание активностей и подписок не включено в текущий Locust-сценарий, потому что эти ручки требуют отдельного исправления обработки camelCase input при включенном `djangorestframework-camel-case`.

Некоторые ответы `400` и `403` считаются ожидаемыми в отдельных сценариях, например повторное сохранение активности, повторная подписка или попытка оценить активность без посещения. Эти ответы помечаются в Locust как успешная обработка бизнес-правила, а не как отказ сервера.

## Метрики для отчета

После прогона из HTML-отчета фиксируются:

- requests per second;
- среднее время ответа;
- медиана;
- 95-й перцентиль;
- максимальное время ответа;
- процент ошибок;
- наличие или отсутствие HTTP 500.

## Очистка данных

Все данные нагрузочного теста имеют префикс `loadtest` в email пользователей и названиях активностей.

После прогона очистка выполняется командой:

```bash
python loadtest/cleanup_loadtest.py
```

Если нагрузка запускалась against Docker-стенда, очистку удобнее выполнять внутри `web`-контейнера, чтобы использовались те же переменные окружения и база `db`:

```bash
docker compose exec web python loadtest/cleanup_loadtest.py
```

Скрипт удаляет только связанные с `loadtest` данные: пользователей, активности, участия, рейтинги, уведомления, подписки, QR-токены, device tokens, сохраненные активности и события ленты.
